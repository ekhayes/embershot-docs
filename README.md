# Embershot Help Docs

Public documentation for Embershot, served at [docs.embershot.com](https://docs.embershot.com).

Built with [Docusaurus](https://docusaurus.io/), deployed to GitHub Pages.

## Local development

Requires Node 22+.

```bash
npm install
npm start
```

Opens [http://localhost:3000](http://localhost:3000) (or 3100 if launched via the workspace preview).

## Adding or editing an article in the browser (no tools needed)

Anyone with write access to this GitHub repo can change the Help Center from github.com.
A change on `main` is live on docs.embershot.com about 2 minutes later, and it also updates
the AI help chat's answers (the build regenerates `help-corpus.txt`).

**Edit an existing article**
1. Find the article on docs.embershot.com and note its address, e.g.
   `docs.embershot.com/sharing-and-links/how-to-share-a-file-with-a-verified-or-open-link`.
2. On github.com open `docs/`, then the folder with the same name (`sharing-and-links`), then the
   `.md` file with the same name.
3. Click the pencil icon (Edit this file), make the change, then click **Commit changes...**.
   Choose **Create a new branch and start a pull request** if you want someone to look first;
   otherwise commit to `main` and it goes live.

**Add a new article**
1. On github.com open the `docs/` folder for the right category (e.g. `docs/sharing-and-links`).
2. Click **Add file > Create new file**. Name it in lower case with dashes, ending in `.md`,
   e.g. `how-to-change-a-link-expiry.md`.
3. Paste the contents of [`ARTICLE_TEMPLATE.md`](ARTICLE_TEMPLATE.md) and fill it in. The `title`
   is the heading shown on the site; `sidebar_position` sets the order inside the category
   (decimals are fine, e.g. `6.3` sits between 6 and 7).
4. Commit as above.

**Add a screenshot**
1. Open `static/img/help/`, click **Add file > Upload files**, upload the PNG and commit.
2. In the article write `![Short description](/img/help/your-file-name.png)` (no `static`).

**Links between articles** use the address without the domain:
`[How to share a file](/sharing-and-links/how-to-share-a-file)`.

**If it does not appear:** the repo's **Actions** tab shows each deploy. A red X means the build
failed (usually a typo in the frontmatter between the `---` lines); open it to see the line, fix
the file the same way, and commit again. The live site keeps the last good version meanwhile.

## Editing content

All articles live under `docs/` as plain markdown. Folder structure becomes the sidebar (autogenerated). Each markdown file needs frontmatter:

```yaml
---
title: "How do I reset my password?"
sidebar_position: 1
---
```

To add a new category, create a folder under `docs/` with a `_category_.json`:

```json
{
  "label": "Account & Billing",
  "position": 2
}
```

## Deploying

Pushes to `main` automatically build and deploy to GitHub Pages via `.github/workflows/deploy.yml`.

DNS: `docs.embershot.com` is configured via the `static/CNAME` file - GitHub Pages picks this up on each deploy.

## Auto-update workflow

A weekly GitHub Action (`.github/workflows/docs-auto-update.yml`) scans recent commits in the source repos (`filetrack-api`, `filetrack-console`, `filetrack-viewer`), uses Claude to identify user-visible changes that may need documentation, and opens a PR with proposed additions/edits.

To enable:
1. Add repository secret `GH_TOKEN_FOR_SCAN` with read access to the source repos.
2. Add repository secret `ANTHROPIC_API_KEY`.
3. Update `scripts/scan-config.json` with the actual source repo URLs.

To trigger manually: Actions tab > "Auto-update docs (weekly scan)" > Run workflow.
